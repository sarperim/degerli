## Notes

- **Root cause (pre-verified by the planner from `dev`; the coder confirms as step 1).** `IdentityServiceCollectionExtensions.cs:37` — `services.AddSingleton<IMailDispatcher, LoggingMailDispatcher>()`. The honest log sink introduced for FLG-04 is the *only* dispatcher, so no code path ever speaks SMTP: the compose.ci `Smtp__*` env targets an adapter that does not exist. The password-reset e-mail is logged ("Outbound e-mail queued for …") and never delivered; TC-ACC-030's `MailpitClient` link wait times out in CI. The builder chose option A for the blocker — fix the test infrastructure — so the fix is the missing adapter behind the existing seam, config-gated so the FLG-04 production posture (real Brevo sender deferred) is untouched. Note this same root cause forced TKT-acc-010's TC-ACC-032 workaround ("run from a seeded verified account — MailPit delivery not wired"); no change needed there, but the real delivery path now exists for future account-mail e2e cases.
- **Implementation guidance.** MailPit in compose.ci needs no auth and no STARTTLS (`Smtp__UseStartTls: "false"` already set) — the BCL `System.Net.Mail.SmtpClient` suffices with **zero new dependencies**; take MailKit only if the BCL client proves insufficient (a dependency addition would need review attention). Keep the dispatcher honest on failure: log dispatch failures without message bodies/tokens (existing `LoggingMailDispatcher` practice + acc-005 review S2 / FLG-04 caveat — scrub adapter exception bodies). Sends must stay fast/bounded so the e2e budget gate holds.
- **Known consequence (routed, non-blocking — do not fix here).** acc-005 review S1: with real (CI) SMTP dispatch the registered-vs-unknown-address timing delta in the reset-request endpoint becomes measurable — already routed to FLG-04 / reset hardening; do not widen the flow's behavior in this ticket.
- **Serialization with TKT-foundation-013 (file-scope audit).** The two tickets are substantively independent (derived-data seeding vs SMTP delivery) but both name `compose.ci.yml` in their allowed scope, so per the disjoint-write-scope rule they are serialized: **014 depends on 013, one group per cycle (P-21 → P-22).** Recorded file lists — 013: `fixtures/**` (+ `compose.ci.yml` only if its approach needs wiring); 014: `src/Api/Mail/**`, dispatcher registration + options binding, `tests/e2e/src/mailpit.spec.ts` (+ `compose.ci.yml` env verification only). If 013 lands with no `compose.ci.yml` diff, the orchestrator may dispatch 014 concurrently at their discretion — the remaining scopes are provably disjoint.
- **Sequencing (for the orchestrator).** After this ticket lands on `dev`: **TKT-acc-009 (PR #50) rebases onto `dev`, re-runs its E2E CI job with TC-ACC-030 executing, and re-enters review.** Do not merge PR #50 before this lands — its E2E job will keep timing out on MailPit delivery.

## Coder confirmation (acceptance #1 — root cause)

Confirmed on `dev` before the fix: `git grep -n Smtp HEAD -- src/ fixtures/` returned **no matches** — no `SmtpOptions`, no `Smtp` section binding, no SMTP client anywhere. `IMailDispatcher` (`src/Api/Mail/IMailDispatcher.cs`) had exactly one implementation (`LoggingMailDispatcher`) and one DI registration (`IdentityServiceCollectionExtensions.cs:37`), so the compose.ci `Smtp__Host: mailpit` / `Smtp__Port: "1025"` / `Smtp__UseStartTls: "false"` env block was consumed by nothing and transactional mail was only logged, never delivered. The fix adds `SmtpMailDispatcher` behind the existing seam and gates the registration on `Smtp:Host`; `compose.ci.yml` needed no change (its `Smtp__*` block was already correct).
