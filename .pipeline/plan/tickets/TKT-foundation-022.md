# TKT-foundation-022: XU100 membership launch-seed — close the real-universe read-path gap (real stocks on the site)

- Status: in-review
- PR: https://github.com/sarperim/degerli/pull/94
- Size: M
- Scope: close the last-mile defect found running the dev stack live (2026-10-18): after PR #93's live-verified chain (`universe-sync` → 651 rows / 646 real instruments; XU030 launch-seed resolved exactly 30 members; prices backfill wrote 150 real rows), **the site still shows only the 16 fixture-universe stocks** — the user checked the running site and saw dummy data. Root cause: the read path (`src/Api/Stocks/StockListEndpoints.cs`, `Universe()`) scopes the covered universe to current XU100 membership (`index.Code == "XU100" && effective_to is null`, FR-RES-001/BR-MDF-005), but the real İş Yatırım universe snapshot (§10.9.8) publishes **instrument rows only, no index-membership rows**, so the job's snapshot-derived cold-start XU100 seed degrades to "no seed" (the `IndexExistsAsync("XU100") == false` branch in `UniverseSyncJob.RunAsync`), and nothing else in the real chain ever writes a real XU100 membership row. **The fix is the TKT-foundation-020 precedent applied to the covered universe: a checked-in, date-stamped `Xu100LaunchSeed`** (sibling of `Xu030LaunchSeed` in `src/Ingestion/Universe/`, same shape — `IndexCode`/`SourceRef`/`AsOfDate`/`Symbols`/`VerificationNote`/`ApplyAsync` — no generalized refactor of the XU030 seed, which would churn its landed tests for no functional gain) seeded from **BIST's published XU100 membership** for the Ekim–Aralık 2026 index period (the same period 020 verified the XU030 list against on 2026-10-18) — **never from the snapshot's instrument set**: the real snapshot publishes 646 instruments, broader than the BIST 100, so seeding XU100 membership from it would mislabel ~546 non-XU100 instruments as covered-universe members; the seed's rows trace to the published XU100 list, not to an inference. Provenance is recorded honestly: `SourceRef = "bist://xu100-launch"` (the rows trace to BIST's published composition, not to an İş Yatırım feed — deliberately diverging from the XU030 seed's `isyatirim://xu030-launch` label, whose verification also traced to third-party listings; a BIST-sourced list labeled `isyatirim` would be a provenance misnomer), `AsOfDate` mirroring `Xu030LaunchSeed.AsOfDate` (2026-10-17, the recorded launch state, so both seeds describe the same launch and the XU030 ⊆ XU100 consistency check is clean at one `effective_from`), and a dated `VerificationNote` documenting exactly where the list was verified (BIST's own published page where reachable; otherwise dated third-party aggregator listings recorded honestly as such — the 020 precedent — never presented as BIST-official). **Market-structure consistency check:** every `Xu030LaunchSeed.Symbols` entry must be contained in the XU100 list (XU030 ⊆ XU100); a violation means one of the checked-in lists is stale — investigate and correct with a re-dated note (the 020 discrepancy precedent), never auto-correct or ignore. **Cold-start wiring (the decision this ticket pins):** the seed is applied by `UniverseSyncJob` — the job that owns membership data — as a sibling step to the existing snapshot-derived cold-start block, gated on **(1) real-source sync** (the fetched universe `SourceRef` is the real İş Yatırım source, `UniverseSourceAdapter.IsYatirimSource` — the canonical L2 stub carries its own ref, so the checked-in real seed never fires in the stub world and canonical goldens stay untouched), **(2) cold-start posture** (the snapshot carries no effective-dated change set — the same guard the existing block uses; a snapshot that does publish change sets hands membership to the FR-MDF-007 change-detection path), and **(3) once-only by the seed's own provenance marker** (no XU100 membership row carrying `bist://xu100-launch` yet — a small `UniverseSyncStore` addition, `HasOpenSeedAsync`-shaped, or equivalent). **Crucially NOT gated on `!HasOpenConstituentsAsync("XU100")`:** the FU world (dev) legitimately pre-populates XU100 with its 16 fixture members (FLG-08), and the real seed must still fire there — the acceptance is real BIST instruments **alongside** the fixture universe in dev. Coexistence is safe by the TC-MDF-062 machinery's own idempotency: `SeedLaunchConstituentsAsync` skips instruments already open or already seeded at the same launch date, so FU's real-symbol members land as `AlreadyPresent`, never duplicated, and a re-run adds nothing and mutates nothing. `ApplyAsync` mirrors `Xu030LaunchSeed.ApplyAsync` exactly: `EnsureIndexAsync("XU100", …)` (idempotent — the FU/L2 world already has the row; untouched), `SeedLaunchConstituentsAsync`, and the shared universe-scope pre-launch coverage gap recorded once behind the existing `HasUniverseSeedGapAsync`/`RecordUniverseSeedGapAsync` guard (FR-MDF-011, BR-MDF-007 — the job already records it independently; the guard makes double-recording impossible). **Unknown symbols are reported, never dropped** (NFR-MDF-003), following the universe job's own seed posture: logged `UNKNOWN_REFERENCE` + quarantined + counted, never silently dropped — and since the real chain is live-verified (646 stored instruments), a live run should resolve all 100 members. **Deliberately out of scope:** `src/Api/Stocks/StockListEndpoints.cs` (the read path is *right* — the defect is missing data, not wrong code; loosening the read scope to all instruments would break FR-RES-001/BR-MDF-005 covered-universe semantics) and `src/Ingestion/Prices/PricesJob.cs` (the XU030 cold-start hook is unchanged — the XU100 seed hangs off the universe job, the XU030 seed off the prices bound; two seeds, two owners, one shared machinery). **Live-endpoint discovery (evaluated, rejected as the shipping mechanism):** an İş Yatırım `Data.aspx`-family membership/constituents resource was probed 2026-10-18 (`Data.aspx/HisseEndeksler` → 401 anonymously on GET; the universe endpoint needed POST — same family), but it is unverified in shape/verb/availability and building the user-visible fix against an unverified resource would repeat the placeholder-endpoint defect TKT-foundation-021 just fixed. The launch-seed is verifiable today; ongoing membership maintenance remains the FR-MDF-007 change-detection path, and live-endpoint discovery is **explicitly deferred** (recorded follow-up, not a landing criterion — an implementer who finds the resource cheaply may record the attempt in the ticket result, honestly, but nothing blocks on it).
