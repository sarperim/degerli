# TKT-foundation-029: data-source provenance disclosure in the product — "where the data comes from" is shown to the user

- Status: in-review
- PR: https://github.com/sarperim/degerli/pull/101
- Size: S
- Scope: **an honest per-data-class source disclosure is added to the product.** User's ask (their words, 2026-10-18): *"i should mention that where data comes from for evds i don't know about kap maybe add it to disclaimers".* This is a disclosure-of-origin surface, distinct from and complementing the existing informational-only disclaimer (FR-MOV-020/UXR-G-016 — the "not investment advice" posture already rendered by `Disclaimer` on research routes). **Placement decision:** the shell footer (`AppShell.tsx`) already carries the global informational-only `Disclaimer`; the provenance disclosure becomes a second footer element — a `DataSourceDisclaimer` rendered **site-wide** (every route, not only research routes — the origin of every data class is answered wherever data is shown). It is a plain footer text element, **not** another `complementary` landmark (the `landmark-is-unique` rule the existing `Disclaimer` variants already respect), so the two never collide. **Copy (tr/en i18n, per data class with its "as of" nature + free-source caveat):** prices/company fundamentals, index levels, universe/sector classification → İş Yatırım public EOD endpoints (XU100/XU030); statements/disclosures → MKK "KAP Data Dissemination Services" (KAP VYK API, via 026); macro series (TÜİK CPI incl. the independent measure, CBRT policy rate, USD/TRY, EUR/TRY, gold) → TCMB EVDS (pending 027's live activation); every class states EOD/as-of nature (not real-time) and that free public-source feeds are used. **Fixture-only worlds are dev-only and never shown as real** — a class with no live values renders an honest `state: unavailable` marker, never a claim of a live source. **Backend decision:** one tiny anonymous read endpoint `GET /api/v1/meta/data-sources` returns the per-class source catalog (id, source name, class, `state: live|unavailable`, "as of" nature) from a **small static product-side catalog** — chosen over a Web-side hardcoded map because honesty is server-owned: macro/KAP liveness changes as 026/027 land and a build-time web bundle would drift; §10.7 already centralizes honest-state in payloads. The catalog is **new static data in the product** — `fixtures/Degerli.Fixtures/RealSourceCatalog.cs` is the test-only parsing-fidelity lane and is never referenced by product code. No DB, no migration, no new model. **Scope stays tight: a disclaimer surface, not a data-licensing module.** Flow-back note: the chosen placement/surface is a UI-atom decision made here — the ux-designer records it in the UX spec ([UXR-G-016] disclaimer lane) per the flow-back standard when this lands.
- Traces to: FR-MDF-008 (the per-fact provenance lineage this mirrors at class level: `isyatirim` / `kap` / `evds`), FR-MOV-020 (the disclaimer family on SCR-001 — this extends the shell's disclaimer surface), FR-SCR-016/FR-RES-017/FR-VAL-008 (the other research disclaimers — the site-wide footer covers them in one place), FR-MOV-009 (as-of attribution), §10.7 honest-state contract (`state: unavailable`, never blank-as-zero — the class-level markers reuse the same language), UXR-G-016 (disclaimers lane); AD-14 / §10.9 (the AD-14 real sources are exactly the disclosed classes — no new source)
