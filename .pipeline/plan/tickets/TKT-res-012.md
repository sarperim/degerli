# TKT-res-012: Valuation history chart — add the missing Recharts Tooltip (date + close)

- Status: in-review
- PR: https://github.com/sarperim/degerli/pull/98
- Size: S
- Scope: frontend-only UI defect fix on the stock page's Valuation section (SCR-005 §2). `ValuationHistoryChart` in `ValuationSection.tsx` renders `XAxis`/`YAxis`/`Line` but no `<Tooltip>` child, so hovering highlights a point (Recharts' default active dot) with no way to read the price or date — user report 2026-10-18 ("it creates a point when i hover my mouse but it doesn't show the price"). The served data is correct; no backend/API change. Add a Recharts `<Tooltip>` that shows, per point, the **date** and the **plotted close** on the chart's honest basis — the `close` value `valuationHistoryPoints` already selected (adjusted when the payload is adjusted, raw otherwise; BR-MDF-010) — formatted with the existing `formatAsOfDate` / `formatNumber` helpers from `src/Web/src/lib/format.ts` using the active locale, consistent with the rest of the screen. The tooltip does **not** add its own basis claim: the figure caption already states the basis (captionAdjusted/captionRaw), and the tooltip value is simply the plotted `close` whichever basis that is. Any tooltip label copy (e.g. the series label "Kapanış"/"Close") goes through the i18n catalogs (`stockPage.valuation.history.*`) with tr+en parity — the CI parity gate owns this, do not inline literals. **Same-gap audit (done at slicing time):** `ValuationSection.tsx` is the only Recharts consumer in `src/Web` (grep for `LineChart|AreaChart|BarChart|ComposedChart|<Tooltip` across `src/Web` matches this file alone); no other chart in the Web app carries the defect, so nothing else enters this ticket's scope.
- Traces to: FR-RES-006, FR-RES-013
- Acceptance (explicit — defect fix; no tooltip-specific TC exists in `.pipeline/testing/`, see follow-up below): (1) `ValuationHistoryChart` mounts a Recharts `<Tooltip>` whose content shows, for the hovered point, the date formatted via `formatAsOfDate(locale, …)` and the close via `formatNumber(locale, …)` — no new formatting code paths, no hardcoded locale or literal; (2) the tooltip value is the plotted `close` (basis-consistent with the caption: adjusted series → adjusted close, raw series → raw close) and introduces no additional adjusted-data claim beyond the existing caption/disclaimer (UXR-RES-020 discipline unchanged); (3) any user-visible tooltip label text comes from the catalogs with tr+en parity (i18n parity test green); (4) the tooltip formatting is testable and tested per the existing conventions — either the date/label/value formatting is extracted as pure helpers into `valuation.ts` (the module's stated convention: pure, DOM- and chart-library-free, unit-testable) and unit-tested for both locales, or the component test asserts the rendered tooltip output (e.g. custom Tooltip content with `data-testid`, Recharts mouse-event simulation in RTL) — pick one, state why, keep it deterministic; (5) existing chart/basis tests stay green — TC-RES-032 (adjusted historical data, `Valuation.test.tsx`) and the `data-testid="valuation-history-chart"` / `data-basis` assertions must not be weakened; (6) CI green on the PR head (lint, typecheck, Web tests, i18n parity). **Test-planner follow-up to record:** `.pipeline/testing/stock-research.md` has no TC pinning chart hover/tooltip behavior for SCR-005 §2 — the test planner should add one (a TC-RES-0xx covering "the historical price chart exposes per-point values (date + close) on hover") rather than this ticket inventing a TC ID.
