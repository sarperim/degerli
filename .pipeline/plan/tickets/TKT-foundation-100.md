# TKT-foundation-100: The durable KAP public-site access fix — adapter TLS shaping, 429-quota awareness, and the export pacing knob (the fingerprint-block and rolling-quota findings; the relay becomes documented ops posture)

- Status: in-review
- PR: https://github.com/sarperim/degerli/pull/161
- Size: M
- **Priority: P1 — the durable half of the live access mitigation (the user's 2026-10-29 deadline rides the orchestrator's relay in the meantime; this ticket removes the product's dependence on it).**
- **The live findings (orchestrator, 2026-10-28/29, relay logs; recorded dated in `01` §10.9.19 by the same planner round):**
  1. **TLS-fingerprint blocking (an escalation of the 087/091 WAF finding to the transport level):** after a burst (~6–18 fetches, process-fresh), the edge starts refusing the .NET `HttpClient` at the **transport level** — connection reset / timeout, "An error occurred while sending the request" from the API container — while curl **and** python urllib from the same host **and from inside the same container** succeed. Began 2026-10-28 ~05:00 UTC, persisted 24 h+. The UA-level fix of 091 is not implicated (the honest token passes); the discriminator is the **TLS ClientHello fingerprint** of the .NET stack.
  2. **A rolling per-IP request quota on the excel export endpoint:** HTTP **429 "Request Limit Exceeded"** — empty body, **no `Retry-After`** — accumulating under heavy use (direct curl also 429s). The `byCriteria` list endpoint is unaffected.
  3. **Timeout interplay:** the app's per-request bound is 30 s; a backoff longer than that outlives its caller and stacks uselessly.
  4. **The orchestrator's live mitigation (dev-only, not a product fix):** a local Python TLS relay (browser-acceptable fingerprint) bound at `Ingestion:KapPublic:BaseUrl` via compose override — single-flight serialization, a **12 s export pacing floor**, brief 429 backoffs. The app's own posture (3 s, single-flight) is unchanged. It works; it is dev-stack tooling.
- **The planner ruling on the durable shape (RECORDED — option (c), both halves):** (i) **adapter hardening is the primary product fix** — the lane's keyed `HttpClient` (`IngestionServiceCollectionExtensions.cs:145`) is constructed over a `SocketsHttpHandler` whose `SslClientAuthenticationOptions` presents a browser-acceptable fingerprint to the extent .NET allows (TLS 1.2+, a browser-shaped cipher-suites policy, ALPN) — **an honest fingerprint, not a disguise**: the `…Degerli/0.1` UA token stays exactly as 091 pinned it, and no header lies beyond what already ships. .NET cannot guarantee a byte-identical browser ClientHello, so the adapter's acceptance is **verified live by the orchestrator's paced probe** before the relay is stood down — the ticket's live criterion, never a CI claim. (ii) **The relay becomes documented ops posture, not a hidden dev hack** — its design (fingerprint, single-flight serialization, export pacing floor, 429 backoffs) is committed under `deploy/` with a README stating when to use it (an edge-behavior shift the adapter cannot absorb) and that `Ingestion:KapPublic:BaseUrl` is the supported seam it rides. **The politeness line, restated because this ticket walks close to it:** presenting a fingerprint the edge accepts while identifying honestly, and **treating the 429 quota as authoritative**, is access posture — not evading limits. No attempt to defeat or round-robin the quota; the backoff honors it.
- **What to implement:**
  1. **The TLS handler** at the keyed-client factory: `SocketsHttpHandler` + `SslClientAuthenticationOptions` (browser-shaped `CipherSuitesPolicy` where the platform allows, TLS floor, ALPN `h2`/`http/1.1`), behind the lane's options so the shape is configurable-equivalent (the 091 UA-pin discipline: shipped config == code default, asserted).
  2. **429 awareness in `KapPublicHttpSourceClient`:** a 429 on any endpoint is a **named, counted outcome** — never a silent retry ladder. `Retry-After` is respected when present; the observed case (absent, empty body) takes a **conservative fixed backoff**. A backoff that would exceed the caller's per-item bound does **not** sleep past it: the walk truncates honestly (the existing budget/ceiling seam, `WALK_*` reasons) and the next pass resumes — a bounded wait, never stacking.
  3. **The export pacing knob:** a separate configurable delay for the excel export endpoint (e.g. `ExportRequestDelayMs`, conservative default pinned from the relay's verified **12,000 ms** floor), applied to detail/report fetches only — the 3 s general pacing for list/identity endpoints is unchanged (the quota findings implicate the export endpoint only).
  4. **The relay, committed as ops posture** under `deploy/` (design + README as ruled above; the live dev override remains an orchestrator ops step, unchanged by this ticket).
- **Pinned non-goals:** no politeness regression — single-flight and the ≥3 s start-to-start general pacing stand (the export floor only raises the export path's); no UA change (091's pin is frozen input); no quota circumvention (no IP rotation, no parallel clients, no header games); no walk-budget semantics change beyond the honest truncation above; no identity/decode/store/serving work (099/101 and the wave own those); no CI call to kap.org.tr, ever.

## Implementation notes (TKT-foundation-100)

### What landed
1. **TLS handler** — `KapPublicHttpHandlerFactory` (`Create` / `CreateSslOptions` / `ParseMinimumTlsVersion` / `ParseAlpn` / `ParseCipherSuites`) in `KapPublicHttpSourceClient.cs`. The lane's keyed `HttpClient` in `IngestionServiceCollectionExtensions.cs` is constructed over it (`HttpVersion.Version20` / `RequestVersionOrLower`). Shipped shape: TLS floor `Tls12` → `Tls12 | Tls13`, ALPN `h2,http/1.1`, an 11-suite browser-ordered `CipherSuitesPolicy` (Linux only; `null` on Windows by platform constraint, asserted as such). `TlsShapeEnabled = false` sets no `SslOptions` (pre-ticket stack).
2. **429 awareness** — `KapPublicHttpSourceClient`: `Retry-After` (delta-seconds or HTTP-date) honored verbatim, otherwise `QuotaBackoffMs` (default 8,000 ms); a wait `>=` the request's per-item bound → `KapPublicQuotaException(Deferred = true, WALK_QUOTA_BACKOFF)` with **no sleep and no re-issue** (the walk truncates); otherwise sleep + **one** re-issue (`MaxQuotaAttempts = 2`), then `QUOTA_RATE_LIMITED`. New reason codes `WALK_QUOTA_BACKOFF` / `QUOTA_RATE_LIMITED` in `KapPublicReasonCodes`; `KapPublicFetchResult.IsQuotaDeferred`.
3. **Export pacing** — `KapPublicRequestKind` (`General`/`Export`) + `PaceAsync(kind, ct)` on `KapPublicRequestPacer`; `KapPublicSourceOptions.DelayMsFor(kind)` with `ExportRequestDelayMs` (default 12,000 ms) for detail/report fetches and the unchanged 3,000 ms general pace for list/identity. A `RequestDelayMs <= 0` disables the floor too (L2 harness binding).
4. **Relay as ops posture** — `deploy/kap-relay/kap-tls-relay.py` + `deploy/kap-relay/README.md` (design, when-to-use, the `Ingestion:KapPublic:BaseUrl` seam); `deploy/README.md` points to it.
5. **Config** — `src/Api/appsettings.json` gains `ExportRequestDelayMs`, `QuotaBackoffMs`, `TlsShapeEnabled`, `TlsMinimumVersion`, `TlsAlpnProtocols`, `TlsCipherSuites` (values as JSON strings, parsed with `GetString()`/`bool.Parse`). The 091 UA pin is untouched.
6. **Docs** — test plan §38 + change record v1.51; architecture §10.9.19 access-posture subsection + change record v1.5.76.
