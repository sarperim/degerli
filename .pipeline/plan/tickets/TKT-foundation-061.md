- **Verified evidence (orchestrator, Thursday night's first truly unattended EOD chain, 2026-10-22):**
  - `corporate-actions` as chain step 5/9 **hung 90 minutes on attempts 1 and 2** → the watchdog correctly bounded both and wrote `RUN_HUNG` rows (185, 190 — verbatim hungJob/step/stepCount; **041's watchdog works**).
  - Attempt 3 got a fast **HTTP 500 from the gateway on `/disclosureDetail/1185709?fileType=data`** (`SourceFetchException`, run 195, 21:52 UTC) — and because the job reports `failed` on any source exception (the adapter's own documented design: `CorporateActionsSourceAdapter.cs:81` "a `SourceFetchException` … the run is recorded `failed`"), the chain **fail-stopped before metrics-recompute / market-snapshot / medians**. **Thursday's close (2026-10-22) never reached the snapshot and the site ran a day stale.**
  - The same CA job completed a full 74-minute walk on Thursday morning (run 173, written 302) — so the hang/500 is **per-disclosure (a specific attachment id), not systemic**.
- **Pinned fix (046's per-constituent precedent, one level down — per disclosure detail):**
  1. **Per-disclosure quarantine-and-continue:** a single un-fetchable disclosure detail (HTTP 500, fault envelope, or transport error) is **isolated** — the walk continues, the skip is recorded honestly (named reason — e.g. `DISCLOSURE_DETAIL_UNFETCHABLE` — with the disclosure index and the error class), quarantined **with evidence** (the gateway's error verbatim in the quarantine record), counted in the run stats, and the run terminates as an **honest partial** — never `failed`, never a silent omission. **Production-honesty pin (recorded per the grant): the answer to per-item gateway errors is quarantine-with-evidence, never silent omission, and never a whole-run failure.**
  2. **Bounded per-item fetch timeout:** the hang class (90 min on one attachment) is bounded by a per-detail fetch timeout (config constant, generous default — the healthy walk paces ~12 s/item over 74 min, so a timeout in the low minutes distinguishes hang from pace), interacting correctly with the lane's pacing and cancellation. After a timeout the item takes the same honest-partial skip path as a 500.
  3. **Family-wide (the 046 scope precedent):** the same per-item isolation lands in all three event-family adapters (dividends, corporate-actions, disclosures — they share the `disclosureDetail` fetch pattern; verified). The chain's step-failure policy is UNTOUCHED — a partial step proceeds, which is what unblocks the chain. **Verification note (not scope):** the statements lane's per-disclosure error posture is checked during implementation; if the identical gap exists there it is recorded on this ticket and sliced as its own follow-up (statements has its own bounded-walk design and is not tonight's evidence).
  4. **Recovery (live criteria):** after the fix lands, the orchestrator re-runs the chain for **2026-10-22 (the missed close)** so the site stops running a day stale — the backfill/repair path is the existing one (admin-triggered chain run for the date), recorded in the live criteria.

## Implementation record (2026-10-23, PR #125)

- **Shape (as pinned, all in scope).** The isolation lives in the shared `VykDisclosureWalker` (`src/Ingestion/Kap/VykDisclosureWalk.cs`) — the only `disclosureDetail` fetch of the three families. New public surface there: `VykDetailSkip` (symbol, disclosure index, `ReasonCode`, failure kind `http`/`fault`/`transport`/`timeout`, status, gateway error verbatim + body excerpt, `ToEvidenceJson()`), `IDisclosureIsolationReporter` (the per-disclosure counterpart of 046's `IVykIdentityIsolationReporter`), `VykDetailTimeoutException`, and `VykCompanyWalk.Skips` (additive; empty when every detail answered). The per-item try covers the **fetch, the raw append and the decode**: an HTTP error (`SourceFetchException` with a status), a **200 `fault` envelope** (each adapter's `DecodeDetail` raises it lazily — `fault` kind, never `transport`), a **transport failure** (`HttpRequestException` — `transport` kind) or a timeout becomes a recorded skip; a `SourcePayloadException` stays fatal (`UNPARSEABLE_PAYLOAD`). The walk logs it and continues, and the listed index still advances the cursor (recorded, never silently dropped). A faulted detail contributes no facts and exactly one skip.
- **Bounded per-item fetch.** `KapSourceOptions.DefaultDetailFetchTimeoutMs` = **180 000 ms (three minutes)** + `DetailFetchTimeoutMs` (`Ingestion:Kap:DetailFetchTimeoutMs`) and `DetailFetchTimeout`. 180 s ≈ 18× the shipped 10 s pace (`Ingestion:Statements:RequestDelayMs`), so a healthy paced walk is never falsely timed out (asserted in TC-MDF-095's guard half). The bound starts **after** `KapRequestPacer`, applies as cancellation *and* a race (an uncancellable client cannot stall the walk), and a caller `CancellationToken` cancellation still propagates (never quarantined).
- **Family-wide wiring (three adapters, three jobs).** Each adapter constructs the walker with the configured bound, clears and exposes `DetailSkips` per run (per-disclosure alongside 046's `UnresolvedSymbols`); each job writes one `quarantined_facts` row per skip (`ReasonCode = DISCLOSURE_DETAIL_UNFETCHABLE`, `SourceRef = kap`, payload = the evidence document) and folds the per-symbol skip count into `symbols[].quarantined` (`failed = false`), so the run ends `partial`. The chain's step policy is untouched (`failed` only fail-stops).
- **Unchanged on purpose:** list-route failures stay fail-fast; malformed detail bodies stay `UNPARSEABLE_PAYLOAD`; 046 identity isolation untouched; the 034 canonical goldens (VYK disabled) byte-identical.
- **Tests (L2 doubles only; no live gateway call was made — the live chain owns the gateway at ≥12 s pacing).** `tests/Api.IntegrationTests/StatementsAndEventsIngestionTests.cs`: `TC_MDF_094_an_unfetchable_detail_is_isolated_and_the_run_ends_partial` (theory, one case per family: HTTP 500 → skip quarantined with the gateway error verbatim, counted, all fetchable rows + cursor written, run `partial`), `TC_MDF_094_a_detail_fault_envelope_is_an_isolated_skip_not_a_failed_run` (HTTP 200 `{"fault":{…}}` on the detail → `fault` failure kind, fault code/message verbatim, no facts from that item, sibling written, cursor advanced, run `partial`), `TC_MDF_094_a_detail_transport_error_is_an_isolated_skip_not_a_failed_run` (a socket-level detail double that resets the faulted index → a genuine `HttpRequestException`, `transport` failure kind, same honest-partial shape; WireMock 2.19's fault model only offers empty/malformed bodies, which arrive as bodies, so the reset is doubled at the socket), `TC_MDF_094_a_partial_corporate_actions_step_keeps_the_chain_steps_reachable` (`metrics-recompute`/`market-snapshot`/`medians` all run non-failed after a partial CA step), `TC_MDF_095_a_stalled_detail_is_bounded_and_takes_the_skip_path` (WireMock 60 s delay + configured 500 ms bound; elapsed bounded, skip path taken, failure kind `timeout`), `TC_MDF_095_a_healthy_paced_walk_is_never_falsely_timed_out` (shipped bound ≥ 10× shipped pace + a 2 s detail ingested normally, zero quarantine).
