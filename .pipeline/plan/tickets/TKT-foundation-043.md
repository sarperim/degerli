# TKT-foundation-043: prices run reported `written 77/100, failed 0` — a per-symbol empty payload is silently uncounted; make no-data symbols visible and countable

- **Priority: P2 — dispatch-ready, investigation-first** (kept separate from 041: the stall is chain ORCHESTRATION between jobs; this is the prices JOB's own accounting — different mechanism, different lane; the prompt's fold-in condition does not hold).
- Verified evidence (dev stack, 2026-10-20): the 20:30 scheduled prices run (ledger run 117) reported `succeeded, written 77/100, failed 0` — **23 constituents were silently absent from the stats** (not written, not unchanged, not quarantined, not failed, not skipped). The 23 appeared normally on the 23:36 re-run (run 118: `written 23, unchanged 75`).
- Planner's code reading (hypothesis, to be confirmed by the investigation): in `PricesJob.RunIncrementalAsync` every symbol ends in exactly one of written/unchanged/quarantined/failed — UNLESS the source serves an **empty payload** for the symbol/date: `UpsertAsync` over zero items returns `Inserted 0, Unchanged 0`, so the symbol contributes **nothing to any counter and nothing to `SymbolRunStat` beyond zeros** — invisible. That matches the signature exactly, and the 23-later-75-unchanged re-run pattern matches İş Yatırım's EOD values being **progressively published at 20:30** (23 tickers' rows not yet served at 20:30, all present by 23:36). Alternative to rule out in the investigation: a source-parsing gap in `PricesSourceAdapter` (a valid payload shape parsed to zero items) — the double-based tests must distinguish "source served no rows" from "source served rows we failed to parse" (the latter must quarantine `UNPARSEABLE_PAYLOAD`, never count as no-data).
