# TKT-foundation-028: market-snapshot job targets the latest stored trading day — cold-start and missed-run catch-up

- Status: todo
- Size: S–M
- Scope: **the `market-snapshot` job's date selection is changed from "always `request.Date` (UTC today)" to "the latest trading day ≤ `request.Date` that has stored prices for the covered universe".** The gap (user-sanctioned, weekend UX, 2026-10-18): the market overview must show Friday's latest snapshot on Saturday/Sunday. The **display logic is already correct** — `MarketEndpoints.cs` serves the LATEST snapshot row (`MarketSnapshots.OrderByDescending(SnapshotDate)`) with `stale` = `SnapshotDate < LatestTradingDayOnOrBefore(today)` (on Saturday that resolves to Friday, so a Friday row serves `stale:false`) — the real gap is **cold start + missed-run catch-up**: `market_snapshots` has 0 rows because the snapshot job only ever computes for UTC-today (`AdminOpsEndpoints` `target = DateOnly.FromDateTime(clock.GetUtcNow())` — no date override; the scheduler's EOD stream is trading-calendar gated and never fires on a weekend), and today is a non-trading day, so it honestly finds no prices and writes nothing. The DB already holds real complete price history back to 2024 (the 025 backfill), so the pipeline should build the snapshot for the LATEST TRADING DAY THAT HAS STORED PRICES — populating the overview now from Friday's real data and self-healing if a trading-day EOD run is ever missed. **Date selection — stored prices are the truth, not a weekday rule:** the existing `LatestTradingDayOnOrBefore` helpers elsewhere are pure weekday-backing and `TradingCalendar.Holidays` ships empty; this ticket resolves the target from `daily_prices` over the CURRENT XU100 membership (the same covered-universe filter `MarketSnapshotEngine` uses), never a weekend/holiday assumption. **Idempotency:** when the latest stored-trading-day already has a snapshot row, the job **no-ops** (skipped — never recomputes/rewrites a completed day); a same-day EOD-chain run still computes because it sees no row yet. When `request.Date` is a trading day with stored prices it behaves exactly as today (TC-MOV-005's one-row-per-trading-day + latest-served semantics preserved). **Honest empty rule unchanged:** no stored price ≤ `request.Date` for the covered universe → the existing null path (`Succeeded`, 0 written, no fabricated row) and the overview keeps serving `state: unavailable` until a real day exists. **Prices job untouched** — the snapshot needs only the latest trading day's prices, which already exist; no backfill re-run, no `prices` date override (scope-creep guard).
