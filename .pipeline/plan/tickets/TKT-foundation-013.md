## Notes

- **Root cause (review-verified on both blocked PRs).** The compose.ci one-shot (`fixtures` service → `FixtureSeedEntry.RunAsync`) migrates, applies the application seed and `FixtureUniverse.Build(FixtureAnchor.NowAnchored)` — prices, index levels, macro, statements, funds, accounts — but nothing ever runs the nightly `snapshot` job or the `metrics-recompute` job: the nightly scheduler never fires inside a CI run, and the admin trigger targets the wall-clock day rather than being part of seeding. So `market_snapshots` and `derived_metrics` stay empty: `GET /api/v1/market/overview` → `state:"unavailable"` (TC-MOV-016/019/020/021 fail on PR #47) and `GET /stocks/ZETA/growth` → `state:"no-data"` (TC-RES-031 fails on PR #54). Both UIs are fully implemented and every other TC passes; only the seeded-stack preconditions are missing.
- **Implementation options (coder's choice, both acceptable to this ticket):**
  - (a) *Invoke the jobs* — extend `FixtureSeedEntry.RunAsync` (after `FixtureSeeder.ApplyAsync`) to compose the jobs' dependencies and run `metrics-recompute` then `snapshot` using the same anchor/`TimeProvider` used to build the fixture set (T = container-start day, so the jobs' "today" is T; `snapshot_date` = T, a seeded trading day). `Degerli.Fixtures.csproj` may gain ProjectReferences to `src/Ingestion` (transitively `src/Core`). Preferred for single-source-of-truth formulas — the jobs were themselves verified against the FU goldens (TC-MDF-026..034, TC-MOV-001..005).
  - (b) *Seed the derived rows directly* — write the `market_snapshots` / `derived_metrics` rows in the fixtures module from the FU §11.1–§11.3 golden values (hand-derived in the plan; never copied from job code). Acceptable fallback if DI composition of the jobs inside the one-shot proves disproportionate.
- **Anchor & ordering rules.** Derived data is produced only after all facts are seeded; assertions/verification use flags/offsets, never wall-clock dates (FU §8.3). Run-ledger rows from option (a) are a welcome side effect (TC-MDF-046 ledger/staleness views).
- **Sequencing (for the orchestrator).** After this ticket lands on `dev`: **TKT-mov-005 (PR #47) and TKT-res-008 (PR #54) must rebase onto `dev`, re-run their E2E CI jobs (TC-MOV-016/019/020/021 and TC-RES-031 now executable), and re-enter review.** Do not merge those PRs before this lands — their E2E jobs will keep failing on the missing preconditions. The re-gate belongs to those tickets, not this one.
