- **What to implement:**
  1. **DR-4 — the BS block state must not forward-fill across the assets→liabilities boundary** (`KapPublicReportDecoder.cs:1283-1312`, emission guard `:726`). Today `BalanceSheetBlockFor` returns the inherited `current` for every non-anchor label, and the state is reset only at `ÖZKAYNAKLAR` — so a body that omits or renames `KISA VADELİ YÜKÜMLÜLÜKLER`/`UZUN VADELİ YÜKÜMLÜLÜKLER` lets every liabilities row silently inherit the **assets** block's scope and take the wrong code (`LT_TRADE_PAY`/`LT_LEASE_LIAB`/`LT_DEFERRED_REV` for a current row) with no finding: the fail-safe guards `null`, never `stale`. **Fix:** reset the block state at the assets→liabilities boundary (e.g. when the total-assets side ends — `TOPLAM VARLIKLAR`/`DURAN VARLIKLAR` end — or on first liabilities-side evidence) so liabilities rows must re-declare a block, and count a named finding (a new closed reason, e.g. `BLOCK_BOUNDARY_UNDECLARED`, or `BLOCK_UNDETERMINED` per the reviewer's alternative — pin the choice into `01` §10.9.19) when a liabilities-side scoped caption would otherwise resolve into an assets block. **Never a silently inherited stale block.**
  2. **DR-5 — the IS part dimension gets a fail-safe and stops resting on one exact string** (`:618-625`, `:1316-1327`). (i) A standalone OCI table is recognized only by `heading == "Diğer Kapsamlı Gelir Tablosu"` verbatim while `StatementTypeForHeading` classifies by `Contains` — a suffixed OCI heading is typed IS but starts in `PL`, silently mapping the OCI `Ana Ortaklık Payları` to `NI_PARENT` (a wrong value under a canonical code, silently). **Fix:** recognize the standalone OCI heading by content, consistent with the classification discipline (e.g. `Contains("Kapsamlı Gelir")` alongside the `Gelir Tablosu` check), and add an IS-scope fail-safe: a caption carrying only a PL-qualified entry appearing where the part is undetermined is a named, counted finding — the IS analogue of `BLOCK_UNDETERMINED` — never a silently defaulted part. (ii) The combined-statement collision path (a differently-worded OCI anchor colliding with `NI_PARENT` → `DUPLICATE_LABEL_CONFLICT` → whole-row quarantine) is counted, not silent, but re-creates the 088 failure mode on the front door: prefer an honest per-row outcome (the undetermined-part passthrough of the fail-safe) over the whole-row quarantine **where the fail-safe already disambiguates** — pin the chosen rule into `01` §10.9.19; do not weaken the conflict quarantine itself (`DUPLICATE_LABEL_CONFLICT` on two genuinely mapped unequal duplicates stands).
  3. **DR-8 — `BLOCK_UNDETERMINED` is emitted per row, not per decoded cell** (`:720-726`). Today the flag is set inside the cell loop after `ReadCell`, so a scoped caption whose only values sit in a skipped (sub-period/undecoded) column produces no finding — contradicting the reason's own doc. **Fix:** compute `scope is null && HasScopedRule(statementType, label)` once per row at the scope assignment and emit when the row is valued on any column (or the caption is scoped and the scope null — pin which, matching the reason's doc wording, into the test plan).
  4. **DR-9 — bounded ride-along at the same emission site:** while rewriting the DR-8 emission, replace `HasScopedRule`'s per-row `rules.Keys.Any` scan with a precomputed per-statement scoped-label set (`IReadOnlyDictionary<string, IReadOnlySet<string>>`) — the reviewer's clarity nit, included only because DR-8 rewrites exactly that site; no other restructuring.
  5. **DR-6/DR-7 — the two assertion strengthenings (TC-MDF-122 cases, same test file):** (h) additionally asserts the declared string is retained verbatim for an unrecognised value (`Assert.Equal("Bireysel", other.Header.ConsolidationType)` beside the existing `Assert.Null(other.Consolidated)` — plan §33 (h) already pins "retained verbatim"); (a) runs the provenance/spelling/registry invariant loop over the **unqualified** projection too, not only the scoped one (plan §33 (a) pins "every entry of both projections"). Pure strengthening — no assertion removed or weakened.

## Implementation record (2026-10-28, implementation lane)

**PR:** https://github.com/sarperim/degerli/pull/156 (branch `tkt-foundation-098`, base `dev`).

### What landed

1. **DR-4 — the BS block boundary.** `BalanceSheetBlockFor` returns `null` for **any label beginning `TOPLAM`**, so every balance-sheet total row closes the block state and the side that follows must re-declare its block; a scoped caption in between resolves to `null` and is counted. **`ARA TOPLAM` subtotals are not boundary rows** (they are not `TOPLAM`-prefixed, so they sit inside a block; making them boundaries would starve the captured non-current blocks and turn well-formed bodies red). The prefix test is side- and depth-blind — **any** `TOPLAM`-prefixed row closes the block, not only a closing one — so a future intra-block `TOPLAM …` subtotal would close the block early and demote the rest of that block's scoped captions to `OTHER_*` + `BLOCK_UNDETERMINED` (named, never a wrong code); only block-closing totals occur on the five committed bodies (review round 1, DR-03). The boundary outcome is the **existing `BLOCK_UNDETERMINED`**, not a new `BLOCK_BOUNDARY_UNDECLARED`: the condition and the outcome are the ones the reason already documents, and a second reason for one condition would split one ledger fact in two (the reviewer's own alternative, pinned in `01` v1.5.74 §10.9.19).
2. **DR-5 (i) — the IS starting part from content.** New `IncomeScopeForHeading(heading)`: `Contains("Kar veya Zarar")` → `PL`, else `Contains("Kapsamlı Gelir")` → `OCI`, else `null` (undetermined). The new closed reason **`PART_UNDETERMINED`** (`KapPublicReportModels.cs`, `02` §6.1) names a part-qualified caption on an undetermined part.
3. **DR-5 (ii) — the stale part.** A part-qualified caption the statement already holds with a **different value**, where a row naming the **other** part sits between the two occurrences (so the part moved and only the anchor's wording was unreadable), falls back to its section-scoped passthrough and is named `PART_UNDETERMINED` (stale wording, distinct from the undetermined-heading wording), instead of colliding and quarantining the whole row. **The conflict quarantine itself is not weakened** — two genuinely mapped unequal duplicates still `DUPLICATE_LABEL_CONFLICT`, and an unequal repeat **inside** its own part (no other-part row between the occurrences) still quarantines the row (TC-MDF-125 (h), added in the ticket's review round 1 — DR-01).
4. **DR-8 — the finding is a property of the row.** `scopeUndetermined = scope is null && !IsNullOrWhiteSpace(label) && HasScopedRule(...) && valueCells.Any(IsValued)`, computed once per row before the cell loop and emitted once after it (IS → `PART_UNDETERMINED`, BS → `BLOCK_UNDETERMINED`).
5. **DR-9 — precomputed membership.** `ScopedLabelsByStatement` (`IReadOnlyDictionary<string, IReadOnlySet<string>>`) built once from `ScopedRules`; `HasScopedRule` is now a set `Contains`.
6. **DR-6 / DR-7 — the assertion strengthenings** in `KapPublicReportDecoderTests.cs`: TC-MDF-122 (h) adds `Assert.Equal("Bireysel", other.Header.ConsolidationType)`; TC-MDF-122 (a) runs the provenance/spelling/registry loop over the **unqualified** projection too (`Assert.NotEmpty` + the four invariants per entry). Nothing removed or weakened.

### Review round 1 (2026-10-28, fixer lane) — DR-01 fixed, DR-02 disputed, DR-03 recorded

Round artifact: `.pipeline/plan/reviews/TKT-foundation-098-round-1.md` (head `d73123f`, diff-reviewer).

- **DR-01 (blocker) — fixed.** The stale-part fallback keyed on the collision alone, and the part state is forward-filled, so a **genuine** unequal duplicate inside the row's own part was diverted into the `OTHER_*` passthrough with a false "no anchor for the other part" detail and the statement row was stored instead of quarantined — contradicting this ticket's pinned non-goal. The fallback now requires the capture's own row evidence that the part moved: a row naming the other part (comprehensive income, or a reclassification — `AttestsOtherComprehensiveIncomePart`, used only here) **between** the occurrence already stored and the colliding one, plus the colliding code being canonical. A same-part repeat has no such row between the two occurrences, so it reaches `Group.Add` → `GroupOutcome.Conflicted` and quarantines the statement row. TC-MDF-125 (e) (the ASELSAN combined statement with its anchor re-worded) stays green — its re-worded anchor is still a row that attests the OCI part — and the new TC-MDF-125 (h) pins the same-part case as a conflict. The false premise ("a caption with a part-qualified entry belongs to more than one part") is corrected on every surface: `01` §10.9.19 + v1.5.74, `02` §6.1, test plan §36 + v1.49, the `PartUndetermined` XML doc, and this record.
- **DR-02 (minor) — disputed as a false positive (evidence).** `BlankFirstValueCells` replaces `title="…"\s*>\s*<display>` with `title=""` + the separator, so the replacement **drops the displayed text as well as the attribute**: the two blanked decoded cells carry no value at all (`IsValued` false for both) and their two lines disappear (314 → 312). Measured on the committed MİGROS body: after the mutation the row's only valued cells are the two sub-period (skipped) columns; blanking those two as well (4 cells) makes the `PART_UNDETERMINED` finding vanish (1 → 0), which proves the finding fires from the skipped columns, not from the blanked decoded cells. The test's name, XML doc and §36 (f) already describe that behaviour; §36 (f)'s step now spells out that both the attribute and the display text are removed, so the mutation's claim is unambiguous. No code change was needed; adding one would have been churn on a passing, correctly-named case.
- **DR-03 (nit) — recorded in the docs, no behaviour change.** The `TOPLAM` prefix test is side- and depth-blind: `01` v1.5.74 (DR-4), `02` §6.1 and §36 now state that **any** `TOPLAM`-prefixed row closes the block (not only a closing one), that a future intra-block `TOPLAM …` subtotal would demote the rest of that block's scoped captions to `OTHER_*` + `BLOCK_UNDETERMINED` (named, never a wrong code), and that only block-closing totals occur on the five committed bodies.
