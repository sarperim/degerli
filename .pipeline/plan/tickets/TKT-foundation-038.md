# TKT-foundation-038: macro freshness lies about monthly series — a `partial` run never counts as success, so TÜFE/Politika Faizi show "Bayat" on their latest PUBLISHED value; make staleness per-series and publication-frequency-aware

- Status: todo
- Size: M
- **Priority: P2 — dispatch immediately after/alongside 036.** User morning check 2026-10-20: TÜİK TÜFE "Veri 1 Eyl 2026 itibarıyla — **Bayat**" and TCMB Politika Faizi "Veri 1 Ağu 2026 itibarıyla — **Bayat**" while showing their latest published values; the daily series (USD/TRY "Veri 20 Eki") correctly show no badge — the daily rule works, the monthly rule doesn't.
- Root cause (planner-verified 2026-10-20 against the live dev database — read-only queries, evidence recorded):
  1. **The failure rule ignores `partial` runs and is job-scoped, not series-scoped.** `MacroFreshnessService.GetStateAsync` (`src/Ingestion/Macro/MacroFreshnessService.cs:64-84`) computes `failureStale = lastFailure > lastSuccess` over the OWNING JOB's ledger, where every non-daily series maps to `MacroCpiJob.Code` (line 60-62). The live `macro-cpi` ledger has **14 `failed` runs (latest 2026-10-19 14:02 — the stale pre-merge container era) and 2 `partial` runs (latest 2026-10-20 06:30, which wrote real TÜIK_CPI/CBRT_REPO rows, `recorded_at 2026-10-20 06:30`) — and ZERO `succeeded` runs ever** (the CPI job lands `partial` honestly: ENAG/INDEP_CPI is admin-entered and never present). So `lastSuccess = null` → `failureStale = true` → **every monthly series is stale forever**, no matter that the freshest real values were written this morning. Daily series are fresh only because `macro-daily` has `succeeded` runs (2026-10-20 05:00) after its failures.
  2. **The monthly age rule is vacuous and not publication-aware.** Tolerance = 31 days measured from `recorded_at` (lines 76-82) — but the CPI job re-records the monthly rows on every run (`recorded_at` refreshes daily: 2026-10-19 19:18 → 2026-10-20 06:30 in the live table), so a flat age-from-`recorded_at` can never catch a genuinely missed monthly publication while the job runs, and it says nothing about publication cadence (TÜFE: month-M data published early M+1; Politika Faizi: ≤2-month meeting cycle).
  3. **The job mapping and the strip envelope compound it.** Admin-entered `INDEP_CPI` (no job writes it, `per_release`) also maps to `MacroCpiJob` → inherits the same false failure-staleness; and the strip-level envelope (`MarketEndpoints`: `stale = series.Any(entry => entry.Stale)`) counts an `unavailable` series' stale flag — so the whole strip reads `stale: true` partly from a series that has never had a value.
- Scope (honest per-series semantics — nothing fabricated in either direction):
  1. **Failure clock per series:** a series is failure-stale only when the owning job's latest failure is NEWER than **that series' own latest `recorded_at`** (the series' stored data is the evidence its ingest succeeded; a `partial` run that wrote the series refreshes its clock). An outright failed run that wrote nothing leaves the clock old → stale stays honest. `INDEP_CPI` (admin-entered, `per_release`, no owning job) is never failure-stale — its honest state is `unavailable` until a value exists.
  2. **Monthly age rule publication-frequency-aware, measured from `asOf` (value date), not `recorded_at`:** a monthly series' latest published value is fresh until its next expected publication window closes — stale when `today > asOf + window`, the window a pinned, documented constant per cadence (**default proposal: 65 days** — covers TÜİK's M+1-early-publication and TCMB's ≤2-month meeting cycle; recorded in `02` §5.6 and adjustable — the shipped constant is what the tests pin; if the user prefers a different window it is a one-constant change, never a semantics change). `per_release` keeps its no-age-window posture (stale only on the per-series failure rule). Daily unchanged (tolerance 1 day from `recorded_at` — the working rule).
  3. **Strip envelope honesty:** the macro response's top-level `stale` aggregates only **available** series; an `unavailable` series contributes its honest `state`, never a stale flag.
  4. **FU world:** the fixture's monthly series are latest-published by construction — they must serve fresh under the new rule; GOLD (daily, `recorded_at = T−10`) stays stale by construction. Any golden delta is pre-listed and honest.
